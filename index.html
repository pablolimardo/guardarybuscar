La pregunta que ordena todo

Toda esta unidad responde una sola pregunta: ¿cómo guardo un montón de datos para poder encontrarlos rápido? Una computadora puede almacenar millones de datos, pero de nada sirve guardarlos si después tarda una eternidad en buscarlos. Cada estructura de datos que vamos a ver es una forma distinta de acomodar los datos, y cada una es buena para algunas tareas y mala para otras.

🎒 Analogía del ropero. No guardás las medias igual que los documentos importantes. Las medias van todas juntas en un cajón (solo importa si están o no). Los documentos van en un fichero con etiquetas (buscás por nombre). Guardar bien es elegir el mueble correcto para cada tipo de dato. Eso es exactamente lo que hace una estructura de datos.

Vamos a estudiar cuatro maneras de acomodar datos —secuencias, arreglos, punteros y árboles— y dos usos típicos: los conjuntos (¿está o no está?) y los diccionarios (clave → valor). Al final vas a poder decidir cuál conviene según el problema.

Conjuntos y diccionarios

Antes de ver cómo se guardan los datos por dentro, veamos para qué los usamos. Estos dos son los usos más comunes.

Conjunto: la pregunta es "¿está o no está?"

Un conjunto (set) es una colección de elementos sin repetidos y sin orden. No te interesa dónde está cada elemento ni cuántas veces aparece: solo si pertenece o no. Es como el cajón de medias: metés medias, y lo único que preguntás es "¿tengo una media roja?".

# Python — conjunto (set)
# Creo un conjunto con 3 elementos, escritos entre llaves { }
sensores = {"nivel", "temperatura", "caudal"}

# .add() agrega un elemento nuevo al conjunto
sensores.add("presion")
# Intento agregar "nivel", pero ya estaba: el conjunto NO lo duplica
sensores.add("nivel")

# El operador "in" pregunta si un elemento pertenece: devuelve True o False
print("caudal" in sensores)   # True: si esta
print("vibracion" in sensores) # False: no esta
# len() cuenta cuantos elementos hay (los repetidos no suman)
print(len(sensores))          # 4
Clave: el conjunto responde in (¿pertenece?) muy rápido y garantiza que no haya repetidos.

Diccionario: la pregunta es "dame el valor de esta clave"

Un diccionario (dict) guarda pares clave → valor. Buscás por la clave y obtenés su valor, sin recorrer todo. Es como un llavero con etiquetas: la etiqueta (clave) te lleva directo a la llave (valor).

# Python — diccionario (dict)
# Creo un diccionario: cada CLAVE (tanque) apunta a un VALOR (temperatura)
temperaturas = {
    "tanque_A": 21.5,   # clave "tanque_A", valor 21.5
    "tanque_B": 18.0,
    "tanque_C": 24.3,
}

# Uso la clave entre corchetes [ ] para leer su valor, sin recorrer nada
print(temperaturas["tanque_B"])   # 18.0
# Si la clave ya existe, asignar un valor la ACTUALIZA
temperaturas["tanque_A"] = 22.0
# Si la clave no existe, asignar un valor la AGREGA como par nuevo
temperaturas["tanque_D"] = 19.5

# .items() me da cada par (clave, valor) para recorrer el diccionario
for tanque, temp in temperaturas.items():
    print(tanque, "->", temp)
Clave: conjunto = solo elementos; diccionario = elemento (clave) con un dato asociado (valor).

Python resuelve estos usos con estructuras internas muy rápidas (tablas hash). Pero para entender cómo se logra esa velocidad, tenemos que ver las cuatro representaciones de abajo.

Representación 1 y 2: secuencias y arreglos

Secuencia / lista: datos uno atrás del otro

La forma más simple: los datos van en fila, en el orden que los fui agregando. En Python es la list. Para saber si un dato está, no queda otra que recorrer desde el principio hasta encontrarlo (o llegar al final). Eso se llama búsqueda lineal.

# Python — búsqueda lineal en una lista
# Una lista comun: los datos quedan en el orden que los escribi
dnis = [27, 15, 42, 8, 33]

def busqueda_lineal(lista, objetivo):
    # Recorro las posiciones de la lista una por una: 0, 1, 2, ...
    for i in range(len(lista)):
        # Comparo el elemento de la posicion i con lo que busco
        if lista[i] == objetivo:
            return i          # coincide: devuelvo la posicion y corto
    # Si termine el for sin encontrarlo, no estaba
    return -1

# Busco el 42: revisa 27, 15, 42 y lo encuentra en la posicion 2
print(busqueda_lineal(dnis, 42))  # 2
Costo: si hay n datos, en el peor caso hago n comparaciones. Lento cuando hay muchos.

Arreglo ordenado: la fila, pero prolija

Si mantengo los datos ordenados, puedo buscar mucho más rápido con la búsqueda binaria: miro el elemento del medio, y como está ordenado, sé si el objetivo está a la izquierda o a la derecha. Descarto media lista en cada paso.

📖 Analogía del diccionario de papel. Para buscar "muela" no leés desde la A: abrís al medio, ves la M, y saltás directo. Cada apertura descarta la mitad de las páginas. Eso es búsqueda binaria.
# Python — búsqueda binaria en un arreglo ordenado
# La binaria SOLO funciona si la lista esta ordenada de menor a mayor
ordenados = [8, 15, 27, 33, 42]

def busqueda_binaria(lista, objetivo):
    # izq y der marcan los limites de la zona donde puede estar el dato
    izq, der = 0, len(lista) - 1
    # Mientras quede al menos un elemento entre izq y der, sigo
    while izq <= der:
        # Calculo la posicion del medio (// es division entera, sin decimales)
        medio = (izq + der) // 2
        # Caso 1: el del medio ES el que busco
        if lista[medio] == objetivo:
            return medio
        # Caso 2: el objetivo es mas chico -> descarto la mitad derecha
        elif objetivo < lista[medio]:
            der = medio - 1
        # Caso 3: el objetivo es mas grande -> descarto la mitad izquierda
        else:
            izq = medio + 1
    # Si izq paso a der sin encontrarlo, no estaba
    return -1

# Busca el 42 mirando el medio y descartando mitades en cada paso
print(busqueda_binaria(ordenados, 42))  # 4
Costo: con n datos, la binaria hace muchas menos comparaciones que la lineal. Cuánto menos lo explicamos abajo con log₂(n).

¿Qué es eso de log₂(n) comparaciones?

Todavía no vieron logaritmos, así que vamos despacio. La idea es simple y sale de una sola pregunta: ¿cuántas veces puedo partir algo al medio antes de quedarme con una sola cosa?

🎲 El juego de adivinar el número. Pensá en "adiviná un número del 1 al 100". Si en cada intento te digo "es más alto" o "es más bajo", la mejor jugada es tirar siempre el del medio. Cada respuesta te deja con la mitad de los números posibles. En muy pocos intentos llegás, aunque el rango sea enorme. Eso es exactamente lo que hace la búsqueda binaria.

Veamos la cuenta con 100 datos. Cada comparación descarta la mitad:

ComparaciónDatos que todavía podrían ser
Arranco100
1ª50
2ª25
3ª12
4ª6
5ª3
6ª1 → lo encontré

Con 100 datos, en el peor caso hago 7 comparaciones, no 100. La búsqueda lineal, en cambio, podría hacer las 100. Esa es la diferencia enorme.

La definición en criollo: log₂(n) es la cantidad de veces que podés partir n al medio hasta llegar a 1. El pequeño 2 significa "partiendo de a mitades". Por eso se lee "logaritmo en base 2 de n".

Y crece muy lento, que es justamente lo bueno:

Cantidad de datos (n)Comparaciones de la lineal (peor caso)Comparaciones de la binaria ≈ log₂(n)

1.000.000.000mil millones30

Leélo así: aunque los datos se multipliquen por mil, la binaria apenas suma unas pocas comparaciones. Duplicar los datos agrega una sola comparación más. Esa es la ventaja de partir al medio, y es la misma razón por la que buscar en un árbol binario de búsqueda es tan rápido: cada nivel del árbol descarta la mitad, igual que acá.

Representación 3: punteros y listas enlazadas

En un arreglo, insertar en el medio obliga a correr todos los elementos de lugar. Los punteros resuelven eso. Un puntero es un dato que no guarda información, guarda la dirección de otro dato: dice "el próximo está allá".

🔗 Búsqueda del tesoro. Cada papelito no tiene el tesoro: tiene una pista de dónde está el próximo papelito. Encadenando pistas recorrés todo. Cada "nodo" guarda su valor y un puntero al siguiente. Eso es una lista enlazada.
# Python — lista enlazada con punteros
# Un molde (clase) para fabricar nodos, cada uno con dos datos
class Nodo:
    def __init__(self, valor):
        self.valor = valor        # el dato que guarda este nodo
        self.siguiente = None   # puntero: por ahora no apunta a nada

# Creo el primer nodo con el valor 27
a = Nodo(27)
# Su puntero "siguiente" apunta a un nodo nuevo con 15
a.siguiente = Nodo(15)
# El puntero de ESE nodo apunta a otro con 42. Queda 27 -> 15 -> 42
a.siguiente.siguiente = Nodo(42)

def recorrer(inicio):
    # Arranco en el primer nodo
    actual = inicio
    # Sigo mientras el nodo actual exista (no sea None)
    while actual is not None:
        print(actual.valor)         # muestro su valor
        actual = actual.siguiente   # salto al que apunta el puntero

# Empieza en "a" y va saltando de puntero en puntero
recorrer(a)   # imprime 27, 15, 42
Ventaja: insertar o borrar un nodo es solo reacomodar punteros, sin mover el resto. Contra: para buscar hay que recorrer siguiendo las flechas (no puedo saltar al medio).

Representación 4: árboles binarios y ABB

Un árbol binario lleva la idea de los punteros un paso más allá: en vez de que cada nodo apunte a uno siguiente, apunta a dos hijos: uno izquierdo y uno derecho. El nodo de arriba de todo se llama raíz, y los de abajo sin hijos, hojas.

La regla de oro del ABB (árbol binario de búsqueda): a la izquierda de cada nodo van los valores menores, a la derecha los mayores. Esa única regla es lo que hace la búsqueda rapidísima.

Buscar en un ABB es como el juego de "adiviná el número" que vimos con log₂(n): comparo con la raíz, y según sea mayor o menor bajo por una sola rama, descartando toda la otra mitad del árbol en cada paso. Por eso un árbol equilibrado se recorre en unos log₂(n) saltos, no de a uno como la lista enlazada.

# Python — árbol binario de búsqueda completo
# Cada nodo del arbol tiene un valor y DOS punteros (izquierda y derecha)
class Nodo:
    def __init__(self, valor):
        self.valor = valor
        self.izq = None    # rama izquierda: valores menores
        self.der = None    # rama derecha: valores mayores

def insertar(raiz, valor):
    # Si llegue a un lugar vacio, aca va el nodo nuevo
    if raiz is None:
        return Nodo(valor)
    # Si el valor es menor, sigo bajando por la rama izquierda
    if valor < raiz.valor:
        raiz.izq = insertar(raiz.izq, valor)
    # Si no, sigo bajando por la rama derecha
    else:
        raiz.der = insertar(raiz.der, valor)
    # Devuelvo la raiz para mantener el arbol enganchado
    return raiz

def buscar(raiz, valor):
    # Si me quede sin nodo, el valor no esta en el arbol
    if raiz is None:
        return False
    # Lo encontre en este nodo
    if valor == raiz.valor:
        return True
    # Es menor: solo puede estar a la izquierda
    if valor < raiz.valor:
        return buscar(raiz.izq, valor)
    # Es mayor: solo puede estar a la derecha
    return buscar(raiz.der, valor)

# Empiezo con el arbol vacio
raiz = None
# Inserto los valores uno por uno en este orden
for v in [27, 15, 42, 8, 33]:
    raiz = insertar(raiz, v)

print(buscar(raiz, 42))  # True: esta
print(buscar(raiz, 99))  # False: no esta

Recorridas y búsqueda

Buscar un dato es una cosa; recorrer toda la estructura para procesar cada dato es otra. En un árbol hay tres recorridas clásicas, según cuándo visito la raíz respecto de sus ramas.

RecorridaOrden de visitaSirve para...
Inordenizquierda → raíz → derechaObtener los datos ordenados de menor a mayor
Preordenraíz → izquierda → derechaCopiar o recrear el árbol idéntico
Postordenizquierda → derecha → raízBorrar el árbol sin dejar nodos colgados
# Python — las tres recorridas
def inorden(raiz):
    if raiz:                       # si el nodo existe (no es None)
        inorden(raiz.izq)          # 1) primero toda la rama izquierda
        print(raiz.valor, end=" ")   # 2) despues la raiz -> sale ORDENADO
        inorden(raiz.der)          # 3) por ultimo la rama derecha

def preorden(raiz):
    if raiz:
        print(raiz.valor, end=" ")   # 1) primero la raiz
        preorden(raiz.izq)         # 2) luego la izquierda
        preorden(raiz.der)         # 3) luego la derecha

def postorden(raiz):
    if raiz:
        postorden(raiz.izq)        # 1) primero la izquierda
        postorden(raiz.der)        # 2) luego la derecha
        print(raiz.valor, end=" ")   # 3) la raiz al final

Combinar estructuras

En la práctica casi nunca usamos una sola estructura. Las combinamos según el problema, como piezas de LEGO. Un caso muy común: un diccionario cuyo valor es una lista.

# Python — diccionario + lista + conjunto trabajando juntos
# Diccionario donde cada clave (tanque) guarda una LISTA de sensores
sensores = {
    "tanque_A": ["nivel", "temperatura"],
    "tanque_B": ["nivel", "caudal", "pH"],
}

# Quiero saber que tipos de sensor hay en total, sin repetir
tipos = set()                    # arranco con un conjunto vacio
# .values() me da cada lista de sensores (sin las claves)
for lista in sensores.values():
    tipos.update(lista)          # agrego todos; los repetidos se ignoran
print(tipos)   # {'nivel','temperatura','caudal','pH'}

# Ahora: que tanques miden pH?
# Recorro cada par (tanque, lista de sensores)
for tanque, lista in sensores.items():
    # Si "pH" esta en la lista de ese tanque, lo muestro
    if "pH" in lista:
        print(tanque)   # tanque_B
Idea: el diccionario da acceso directo por tanque, la lista guarda varios sensores por tanque, y el conjunto elimina repetidos. Cada estructura hace lo que mejor sabe.
